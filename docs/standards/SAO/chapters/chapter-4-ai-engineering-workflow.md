# Chapter 4: The Tri-Core AI Engineering Workflow

## 1. Purpose
In the SHRS Ecosystem, Artificial Intelligence is not treated as a single monolith. Different LLMs (Large Language Models) possess different strengths. To maintain the highest quality of engineering, SHRS officially adopts the **Tri-Core AI Workflow**. This workflow explicitly defines how Gemini, Claude, and ChatGPT interact to design, build, and audit the Soul-Hunter ecosystem.

## 2. The Tri-Core Roles

### 2.1 The Chief Architect (Gemini / Agentic AI)
- **Role:** System Design, Governance Enforcement, and Repository Management.
- **Responsibility:** Defines the Blueprint, writes technical documentation, creates folders/files, and manages GitHub commits.
- **Rule:** Gemini is the ONLY AI authorized to make direct changes to the canonical repository or architecture.

### 2.2 The Implementation Coder (Claude 3.5 / Equivalent)
- **Role:** Code Generation and Syntax refinement.
- **Responsibility:** Writes the actual Unity C# scripts, game logic, and mechanical implementations.
- **Rule:** Claude MUST strictly follow the Blueprint generated by Gemini. Claude is NOT allowed to invent new architectural patterns that contradict the SHRS Constitution.

### 2.3 The Debugger (ChatGPT / GPT-4)
- **Role:** Error Resolution and Stack Trace Analysis.
- **Responsibility:** Fixes immediate runtime errors, Unity console warnings, and syntax bugs.
- **Rule:** ChatGPT's scope is strictly limited to fixing isolated bugs. It must not refactor the entire system architecture to fix a local bug.

## 3. The Execution Lifecycle

When a new feature (e.g., "Player Controller") is required, the development MUST follow this sequence:

1. **Phase 1: Architecture (Gemini):** The Human Founder instructs Gemini to design the "Player Controller". Gemini generates the `Technical Doc (Markdown)` detailing the exact classes, single responsibilities, and Event Bus interactions. Gemini commits this blueprint to the repository.
2. **Phase 2: Implementation (Claude):** The Human Founder copies the `Technical Doc` and hands it to Claude with the instruction: *"Write the C# code exactly as specified in this blueprint."* Claude produces the scripts.
3. **Phase 3: Validation & Debugging (ChatGPT):** If the scripts throw Unity errors, the Human Founder feeds the errors and scripts to ChatGPT to fix the immediate bugs.
4. **Phase 4: Audit (Gemini):** The final, working C# code is brought back to Gemini. Gemini audits the code to ensure no SHRS architectural rules were broken during Phases 2 and 3. If approved, Gemini commits the code to the repository.

## 4. Conclusion
By separating Architecture (Memory & Discipline) from Implementation (Syntax Generation) and Debugging (Pattern Recognition), SHRS achieves a highly resilient, scalable, and flawless engineering output.
